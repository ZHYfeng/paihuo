# Task 资源清理

## 目标

Task 的 SQLite 历史、Runtime 会话目录、tmux 运行文件和 Git worktree/分支必须有一致的生命周期；历史清理不能只删数据库记录。

## 决策

- 失败/取消或仍待审批、待合并的任务保留 `sessions/.runtime-sessions/<实例>/task-<id>`，供重做和续跑复用；已经成功交付且不可再续跑的代码任务（成功合并、无改动跳过合并）立即回收 Runtime 会话。其余任务进入历史清理时，同步删除 Runtime 会话目录、tmux 运行文件、worktree、分支和 Git worktree 注册。
- 手动历史清理和自动历史清理使用同一批任务快照；先让 Store 原子删除任务，再按快照清理磁盘资源，并执行孤儿 Runtime 会话对账。资源清理失败必须记录并返回，不再静默把资源遗留当成成功。
- 已成功整合到主分支的合并任务，以及对应源任务的代码 worktree/分支立即清理；待审批、失败、取消或合并失败的 worktree 保留到显式删除或保留期限到期。
- 自动 worktree 保留清理使用统一的 `Discard` 路径，既处理实际目录，也处理目录已被外部删除后的 Git 注册和分支；不能依赖任务数据库记录仍存在。

## 验收

- 历史清理后，不再存在已删除 Task 对应的 `.runtime-sessions/.../task-*`、tmux 运行目录、worktree、分支或 Git worktree 注册。
- 自动清理不会因为先删除任务记录而失去清理 worktree 所需的路径/分支信息。
- 成功合并路径和无改动跳过合并路径都会清理代码工作区；冲突/失败路径保留重试所需工作区。
